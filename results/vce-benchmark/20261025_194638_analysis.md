MPS inference was about 2.76x faster than the best tested CPU variant (94.871 / 34.338). The 45-second quick run showed the same ordering: MPS 19.234 seconds vs CPU 51.025–52.702 seconds.

The test reported 0.0% WER vs MPS for each CPU transcription. That measures agreement with the MPS transcript, not independently validated accuracy against a ground-truth transcript.

## Patch decisions

1. Set `whisper_acceleration=true`, `enable_mlx_whisper=false`, and `enable_stage_timing=true`, preserving the rest of the user's settings. CPU Whisper is not made the default because it was substantially slower on this Mac.
2. Do not globally reduce VLM resolution or change scene segmentation parameters: this benchmark did not measure visual accuracy across those parameters.
3. On a genuine MLX/Metal memory-allocation error, clear unused caches and retry at 384 px, then 320 px with one representative keyframe, then 256 px with one keyframe. If all retries fail, unload VLM, mark the visual description as skipped, disable further VLM calls for the current video, and continue with audio/OCR rather than failing the whole job.
4. For known malformed MP4 container errors, try a non-destructive FFmpeg stream-copy remux into a temporary file and validate the result. The original is never overwritten. If recovery fails, stop before model loading and give a specific re-download/re-export recommendation.

## Limitations

This benchmark tested Whisper only. It did not assess scene accuracy, visual-caption quality at different resolutions, or concurrent CPU Whisper + GPU VLM execution. Lower-resolution retries are an emergency memory fallback, not a claim of equal visual quality. A remux may recover some damaged containers, but cannot reconstruct missing media data if the source is truncated or structurally unrecoverable.


## Scope limitation and runtime policy

The numbers above compare Whisper backends **in isolation**. They do not prove that MPS Whisper gives the shortest total analysis time when it competes with the GPU-resident VLM. The intended production strategy is CPU Whisper overlapped with GPU VLM; therefore the recovery patch keeps `whisper_acceleration=false`, `enable_mlx_whisper=false`, and stage timing enabled. A full concurrent end-to-end benchmark is still needed before changing that policy. The current recovery patch improves Metal-OOM resilience and damaged-container handling; it does not, by itself, create task-level concurrency.
