# Native Text JSON failure and isolated mitigation

The PR61 RAM matrix stopped on analysis 7 (first input of repeat 1, queue size 3, RAM+), after six successful analyses and four completed queues. It was not the third item in the queue. HTTP 200 carried Text LLM status failed; primary and repair lacked a complete JSON object with nonempty executive_summary. No source content was discarded.

Whisper large/MPS, Qwen3-VL-8B and Qwen3.5-9B/Metal were used, full original budgets (1024/2048/8192). The controller stopped without restarting. Free memory minimum was 17%, above the 15% floor. This is not evidence of a RAM-mode causal failure. The same video previously succeeded. Transcript/OCR hashes match, but VLM summaries differ, so those prompts were not identical.

The base and PR61 Text postprocess function ASTs are identical except final cleanup. Primary explicitly enabled thinking despite the nearby comment requiring constrained extraction without long reasoning. Repair already disabled it. The failure showed output budget consumed without valid structured output. The patch disables thinking consistently at primary chat template, stream and fallback; removes the irrelevant thinking budget. It preserves token budgets, validation, repair and source fallback. This is a bounded mitigation, not proof that every possible invalid model response is fixed.

Regression suite: 295 unittest cases passed. New AST contract tests cover primary/repair thinking flags and absence of contradictory thinking-budget requests. Native replay and new matrix results are recorded separately, with different engine versions never pooled. Installed app and persistent settings are unchanged.

## Follow-up matrix: distinct memory failure

At commit71f59b6, three queues/four full analyses passed Text JSON. The next queue (repeat1 queue2 RAM+, first input) crossed the15% free-memory guard: last sample13%. Polling every10s observes a threshold after crossing; it cannot reserve RAM. The generic stream exception handler then retried generation with the same model. Cleanup wait90s timed out and overwrote the original safety exception. Additional patch: propagate recognized GPU allocation errors in both primary and compatibility stream exception handlers rather than retry identical generation. Regression exercises the actual extracted handlers with Metal OOM and ordinary compatibility errors. The external harness is separately hardened: sample every1s, conservative20% guard, preserve primary_error, record cleanup, and terminate then kill ONLY owned Popen children after a bounded3s grace. Synthetic process tests cover normal shutdown and ignored SIGTERM. This does not prove the large RAM+ model set is safe under concurrent Mac load; no full restart until that condition is established. No existing app or system setting changed.

## RAM-minus capacity: incomplete structured output without memory pressure

The separate RAM-minus five-input queue at ada3fd8 stopped on input4 after three successful analyses. Minimum free memory was50%, no OOM; input5 was not attempted. The primary started with a JSON object (offset0,7728 characters), and the saved tail ended after its uncertainties array without a root closing brace. Full historical raw was not saved, so this is evidence for a missing root delimiter, not proof that there were no other syntax defects. Same frozen input replay at seed0 on unchanged code succeeded, demonstrating nondeterministic failure.

A conservative repair now precedes the optional json_repair dependency: append ONLY one root `}` if strict decoding then proves all six expected fields, expected top-level types and a nonempty summary. Duplicate keys and nonstandard constants are rejected; cut strings/arrays, missing fields, extra prose and reasoning remain failures. Content is not invented, and the existing downstream validation still runs. The optional dependency being absent must not discard this strict result. This does not guarantee generation completeness or factual quality. Tests cover refusal cases, and a syntax fixture made by removing the final brace from an actual valid case4 output restores exactly the same parsed content. The latter is a deliberate mutation, not a recovered historical failed raw.
