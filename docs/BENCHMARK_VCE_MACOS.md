# Измерение производительности VideoContext Engine на macOS

Скрипт scripts/benchmark_vce_macos.py запускает анализ выбранного локального видео через локальный VCE API и сохраняет отчёт без текста транскрипции или визуальных описаний.

## Что измеряется

- Wall time на стороне клиента, включая передачу файла локальному API.
- Время обработки VCE, длительность видео, число сцен, модели и основные параметры запроса.
- Доступные в ответе API тайминги Whisper, VLM и timings.stage_diagnostics.
- CPU% и RSS дерева процесса, которое слушает порт 7555, с интервалом по умолчанию 2 секунды.
- Метаданные видео через ffprobe, если он установлен.
- Версия macOS, архитектура, число CPU, объём памяти и показатели vm_stat.
- Наличие маркеров трёх патчей в локальном исходнике, а также предупреждение, если сервер мог быть запущен до последнего изменения файла движка.

Скрипт использует только стандартную библиотеку Python. Он не редактирует движок и не меняет videocontext_settings.json. Чтобы не создавать тестовые TXT/JSON-результаты в папке сервера, флаги генерации файлов выключаются только в HTTP-запросе бенчмарка.

## Запуск

1. Убедитесь, что VideoContext Engine запущен, а другой анализ не выполняется.
2. Скачайте скрипт:

   curl -fL "https://raw.githubusercontent.com/shushpanchik-art/VideoContext-Engine-Apple-Silicon/feat/vce-parallel-cpu-asr-vlm-20261025/scripts/benchmark_vce_macos.py" -o "$HOME/Desktop/benchmark_vce_macos.py"

3. Запустите один контрольный прогон, заменив путь на свой:

   python3 "$HOME/Desktop/benchmark_vce_macos.py" --video "$HOME/Movies/test.mp4"

4. Для более надёжного сравнения повторите один и тот же видеофайл трижды:

   python3 "$HOME/Desktop/benchmark_vce_macos.py" --video "$HOME/Movies/test.mp4" --runs 3

Программа попросит подтвердить запуск словом RUN. Не запускайте её параллельно с другой задачей VCE: замеры будут искажены и появится конкуренция за CPU/GPU/RAM.

Если проект установлен не в ~/VideoContext-Engine и не в ~/Downloads/VideoContext-Engine, укажите путь через --project "/точный/путь/VideoContext-Engine".

## Что будет создано

В новой папке VCE-Benchmark-YYYYMMDD_HHMMSS на Desktop (или в домашней папке, если Desktop отсутствует):

- report.json — полный отчёт с числовыми метриками;
- summary.md — короткая таблица для чтения;
- resources.csv — временной ряд CPU/RSS во время запросов.

Приложите report.json и summary.md к сообщению в ChatGPT; resources.csv полезен при анализе скачков нагрузки и памяти.

## Приватность

Скрипт отправляет видео только на локальный адрес 127.0.0.1:7555, как обычный локальный запуск VCE. Он не отправляет видео или отчёт в GitHub и не записывает абсолютный путь или имя исходного видео, текст транскрипции, описания сцен, глобальную сводку или пользовательские промпты. В отчёте остаются технические параметры, модели и агрегированные размеры текстовых полей.

## Публикация отчёта в GitHub (по желанию)

Чтобы сохранить результаты в репозитории для последующего разбора, нужен GitHub CLI (gh), авторизованный пользователем с правом записи в репозиторий. Один раз выполните gh auth login, затем запустите тест так:

   python3 "$HOME/Desktop/benchmark_vce_macos.py" --video "$HOME/Movies/test.mp4" --runs 3 --publish-github

После измерений скрипт попросит отдельно ввести PUBLISH. Только после этого он отправит report.json, summary.md и resources.csv в папку results/vce-benchmark/ с меткой времени в экспериментальной ветке feat/vce-parallel-cpu-asr-vlm-20261025. GitHub CLI использует ваш локальный вход; токен не сохраняется в отчёте и не выводится.

Репозиторий публичный, поэтому опубликованные файлы будут доступны публично. Перед подтверждением проверьте, что вас устраивает публикация метаданных компьютера, названий моделей, параметров анализа и таймингов. Путь/имя видео, тексты распознавания, описания сцен, итоговая сводка и пользовательские промпты в отчёт не включаются. Без флага --publish-github публикация не выполняется; файлы остаются только локально.

## Ограничения интерпретации

- client_wall_s включает передачу файла; server_process_time_s измеряет обработку по часам VCE. Они не должны быть одинаковы.
- frame_prefetch_wait_seconds, frame_prefetch_worker_seconds и frame_prefetch_fallback_count появляются только если текущая сборка API их возвращает. Если stage_diagnostics нет, отчёт всё равно сохранит остальные тайминги.
- CPU/RSS относятся к процессу VCE и его потомкам, а не ко всем приложениям Mac.
- Скрипт не пытается получать GPU utilization через powermetrics: эта операция часто требует повышенных привилегий. Время инференса VLM фиксируется отдельно, но не является прямым показателем загрузки GPU.
- Текущий запуск измеряет установленную конфигурацию. Для доказательства ускорения от prefetch нужно сравнить результаты до/после при одинаковых настройках, видео и состоянии кеша; не делайте вывод по одному прогону.
